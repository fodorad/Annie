annie.core.runtime
==================

.. py:module:: annie.core.runtime

.. autoapi-nested-parse::

   Launch-time helpers for running Annie as an installed desktop app (infrastructure).

   Concerns of the installed app rather than of the UI, kept out of :mod:`annie.app` and
   :mod:`annie.desktop` so they can be unit-tested:

   * **FFmpeg DLLs on Windows.** Since Python 3.8, Windows no longer searches ``PATH`` for
     the DLLs an extension module depends on, so torchcodec cannot find FFmpeg's
     ``avcodec-*.dll`` & co. unless their folder is registered with
     :func:`os.add_dll_directory` before torchcodec is imported.
   * **No console windows.** The installed Annie runs without a console (``pythonw``), so
     every ffmpeg/ffprobe it starts would get a console window of its own, flashing on
     screen; :func:`hidden_console` keeps them hidden.
   * **A second launch.** Double-clicking the shortcut while Annie is already running must
     open the running instance instead of crashing on a busy port.
   * **Launcher age.** The Windows installer's launcher (``installer/windows/launcher.pyw``)
     stamps its version into ``ANNIE_LAUNCHER_VERSION``. Annie itself updates on every
     start, but the launcher, the bundled Python and FFmpeg only change when the user
     reinstalls, so Annie tells them when that is needed.
   * **Updates.** The tray's "Check for updates" compares the running version with the
     newest release on PyPI.
   * **The Annie folder.** The tray opens the folder that holds Annie's program and data.
   * **Example datasets.** The installer can include two small example datasets; the tray
     downloads them later when they were left out.

.. py:data:: REQUIRED_LAUNCHER_VERSION
   :value: 3


   Oldest ``installer/windows/launcher.pyw`` version this Annie works with.

   Bump this together with ``LAUNCHER_VERSION`` in the launcher whenever the launcher, its
   bundled Python or FFmpeg changes in a way this Annie relies on. Version 2 is the tray
   launcher with the bundled Python; installs still running ``Annie.cmd`` (version 1) are
   asked to run the new installer. Version 3 bundles the Visual C++ runtime next to that
   Python, which PyTorch needs on PCs without the system-wide Redistributable.

.. py:function:: ffmpeg_dll_dir(override: str | None, ffmpeg_exe: str | None) -> pathlib.Path | None

   Return the folder holding FFmpeg's shared libraries, or ``None`` if unknown.

   On Windows the DLLs sit next to ``ffmpeg.exe`` in a shared build's ``bin`` folder.

   :param override: The ``ANNIE_FFMPEG_LIB_DIR`` value, if any; wins when it is a folder.
   :param ffmpeg_exe: The ``ffmpeg`` executable found on ``PATH``, if any.

   :returns: The folder to register, or ``None`` when neither source points at one.


.. py:function:: hidden_console(platform: str = sys.platform) -> int

   The :mod:`subprocess` ``creationflags`` that keep a console program out of sight.

   When a program without a console (the installed Annie runs under ``pythonw``) starts
   a console program such as ffmpeg or ffprobe, Windows opens a new console window for
   it, which flashes on screen for every video. ``CREATE_NO_WINDOW`` gives the child a
   console it can write to, without a window. Other platforms need no flags.

   :param platform: ``sys.platform``, injectable for tests.

   :returns: ``CREATE_NO_WINDOW`` on Windows, else ``0`` (no flags, valid everywhere); pass it
             on as ``subprocess.run(cmd, creationflags=hidden_console())``.


.. py:function:: ensure_windows_ffmpeg_dlls() -> pathlib.Path | None

   On Windows, register FFmpeg's DLL folder so torchcodec can load it.

   Idempotent and a no-op on other platforms. Call before importing torchcodec.

   :returns: The folder registered by this call, or ``None`` if nothing was registered.

   :returns: ``True`` only for a readable version below :data:`REQUIRED_LAUNCHER_VERSION`.


.. py:function:: parse_version(raw: str) -> tuple[int, ...] | None

   Return the numeric release part of a version string, or ``None`` if there is none.

   ``"1.12.0"`` gives ``(1, 12, 0)``. Anything after the release numbers (``.dev3``,
   ``rc1``, ``+g1a2b3c``) is ignored, so a development build of 1.13.0 compares equal to
   the 1.13.0 release rather than newer.

   :param raw: A version string such as ``"1.12.0"`` or ``"v1.12.1.dev2+gabc"``.


.. py:function:: is_newer(latest: str, current: str) -> bool

   Return whether release ``latest`` is newer than the running ``current`` version.

   Unreadable versions never count as newer, so a garbled answer from PyPI cannot
   trigger an update. Missing trailing parts count as zero (``1.12`` equals ``1.12.0``).


.. py:function:: latest_pypi_version(timeout: float = 5.0) -> str | None

   Return the newest Annie release on PyPI, or ``None`` when PyPI cannot be reached.


.. py:function:: annie_folder(settings: annie.core.config.Settings, install_dir: pathlib.Path | None) -> pathlib.Path

   Return the folder the tray's "Open Annie folder" opens.

   With the installer's defaults that is ``%USERPROFILE%\Annie``, which holds both the
   program (``App``) and your work (``Data``). When the two were put in unrelated
   places, or Annie was not started by the Windows launcher, it is the data folder.

   :param settings: The running app's settings, which know where the data lives.
   :param install_dir: The ``ANNIE_INSTALL_DIR`` folder, or ``None`` when not installed.


.. py:function:: examples_installed(directory: pathlib.Path) -> bool

   Whether the example datasets' configs are in ``directory`` (an ``ANNIE_DATA_DIR``).


.. py:function:: extract_examples(archive: pathlib.Path, directory: pathlib.Path) -> int

   Unpack the examples archive into ``directory`` and return the number of files.

   Only entries under ``config/`` and ``example/`` are extracted, and none may escape
   ``directory``, so a damaged or hostile archive cannot write anywhere else.

   :param archive: The downloaded ``annie-examples.zip``.
   :param directory: The ``ANNIE_DATA_DIR`` folder; created when missing.

   :raises ValueError: If the archive holds no example configs.
   :raises zipfile.BadZipFile: If it is not a zip archive.


.. py:function:: download_examples(directory: pathlib.Path, timeout: float = 60.0) -> int

   Download the example datasets into ``directory``; see :func:`extract_examples`.

   The archive is kept inside ``directory`` only while it is unpacked.

   :raises OSError: If the download fails.
   :raises ValueError: If the download is not a valid examples archive.


.. py:function:: decoder_problem(exc: BaseException, platform: str = sys.platform) -> str

   Explain why the frame decoder (torchcodec, and PyTorch under it) could not load.

   On Windows the usual cause is a missing Microsoft Visual C++ runtime: PyTorch's DLLs
   need ``msvcp140.dll`` & co., which neither Windows nor Python always provide. The
   Windows installer bundles them; installs made before that, and other setups, need
   the system-wide Redistributable.

   :param exc: The ``ImportError``/``OSError`` raised while importing the decoder.
   :param platform: ``sys.platform``, injectable for tests.

   :returns: A one-line message for the Log tab, the toast and the banner.
